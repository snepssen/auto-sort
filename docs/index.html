A Downloads folder that empties itself.

auto-sort works out what each file actually is, learns how a folder is organised from the folder itself, and files everything into the folders your computer already has. It moves nothing it cannot explain, and it can undo all of it.

Get it on GitHub How to start it

Almost everything unwanted on a computer arrived through the Downloads folder. It is not somewhere anybody keeps things — it is where files land on the way to somewhere else — so auto-sort treats it as a funnel: everything leaves, and nothing is kept back. A sorter that files the half it recognises and abandons the rest has emptied nothing.

How it decides

Four readers, cheapest first, each allowed to overrule the one before it when it has better evidence. No models, no network, no cloud.

  • The extension — 600 of them across 13 kinds. Right most of the time, free, and never trusted further than likely.
  • The bytes — 145 magic numbers, plus refiners for the containers several kinds share. PK\x03\x04 is a zip and also every Office document, EPUB, Android package and USDZ model ever made.
  • The header — EXIF, ID3, Vorbis, MP4 atoms, Matroska, RIFF, PDF info. Camera and capture date; artist and album; duration and track layout; producer and page count.
  • The name, and where it came from — filename conventions, and the download URL your operating system already recorded. That last one is the sharpest evidence available and almost nothing uses it.

Every fact carries its source and a confidence. A stronger source overrules a weaker one and the disagreement is kept. Agreement raises confidence — an artist from an ID3 tag is strong, the same artist also parsed from the filename is stronger. A fact that could not be established is absent rather than empty, so a missing reader narrows what can match instead of making it match wrongly.

It learns the folder, rather than being told

Structure it derives

auto-sort propose surveys a folder, counts the groupings that actually exist, and writes the rules that folder turns out to need — with the counts that justified each one written above it. What it refuses matters more than what it proposes: a folder per artist was declined on a real Downloads folder because twenty-one artists across forty-three files means the middle folder holds one picture. That is the same pile with more steps.

Conventions it works out

A naming convention is, by definition, something that repeats — so it can be counted rather than tabulated:

In a filename written by software, a field that repeats across many files is a category; a field different in every file is an identifier.

Given forty-three files shaped <digits>.<word>_<rest>, the digits are all different and the words repeat, so it writes a rule capturing the word. Nothing in the code knows what that site is. There is no table of websites anywhere in the project, and nothing ever contacts one.

What you correct

The ledger says where each file was put; the disk says where it is. Any difference is you disagreeing, and where you moved it to is the answer. auto-sort corrections reports which rules you kept overriding — often more useful than any guess — and proposes a rule when enough corrections agree. It proposes; it never silently adjusts.

What it filed too early

A folder reveals itself gradually, so the files that arrive first are always filed worst. auto-sort regroup goes back for them, moving what is sitting in a holding folder into structure that has since become visible — without anybody dragging files back into Downloads. Only provisional placements are revisited, so it is idempotent and cannot reshuffle a disk.

It is careful, and it can be undone

  • Dry run by default, and the first real run against any folder is forced to a preview you have to look at first.
  • Everything is in a ledger — source, destination, size, content hash, the rule that fired. auto-sort undo walks it backwards, including the empty folders it created.
  • Nothing is ever deleted. Not duplicates, not junk. The strongest action available is a move.
  • Nothing is overwritten. Collisions get a suffix.
  • Cross-volume moves copy, verify by hash, then remove — never the other order. An external drive is sorted in place rather than dragged onto your system disk.
  • It never touches the network, and it is not a cloud service. There is nothing to sign up for.

Running it

Double-click Start auto-sort.command on macOS, start.sh on Linux, or start.bat on Windows. It writes a rules file if there is not one, tells you what it is about to watch, points out that dry run is on, and then runs — leaving an icon in the menu bar and a log page behind it. None of that requires knowing what Python is.

From a terminal, if you prefer:

auto-sort propose ~/Downloads --out my-rules.ini   # what this folder needs
auto-sort sort ~/Downloads --rules my-rules.ini    # see what it would do
auto-sort explain FILE                             # why one file goes where
auto-sort undo last                                # take it all back

Requirements

Python 3.8 or newer, and nothing else — no pip install, on any platform. Reading headers, learning conventions, deciding, moving files and remembering all of it are done with struct, re, os and sqlite3, which every Python already has. Even the menu bar icon has no dependency: it is built on the Objective-C runtime through ctypes, the same way the Windows one is built on Shell_NotifyIcon.

ffprobe and exiftool are used if they happen to be installed, and the launcher offers them. Declining both still leaves a working sorter; what is lost is durations for a few container formats and metadata for a few unusual cameras.

What it deliberately does not do

  • Look at content. No image, audio or video recognition. Files named after their own checksum carry nothing to sort by, and the report says how many there are rather than pretending otherwise.
  • Talk to anything. No metadata lookups, no accounts, no telemetry. A tool with unattended access to a whole disk should not have a network habit.
  • Rename your film library. That is Radarr's job and it is better at it.
  • Delete. Ever.
